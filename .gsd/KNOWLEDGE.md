# Knowledge

- In `.gsd` toolbox worktrees, `go test` can resolve package paths through the linked `/home/mackross/dev/toolbox` checkout instead of the active worktree. When that happens, run tests with `GOWORK=$(pwd)/go.work go test ...` so Go uses the current worktree's files. (The simpler `GOWORK=` override is sufficient; `env -u PWD GOMOD=` is not needed.)
- For pseudo-version fixture and resolver tests, derive the `v0.0.0-<timestamp>-<sha>` timestamp from `git show --format=%cI` and normalize it to UTC. Handwritten timestamps drift from actual commit metadata and cause false failures once timestamp validation is enforced.
- The local GitHub emulate test server does not implement `GET /repos/{owner}/{repo}/git/ref/tags/{tag}`. When testing provenance-aware GitHub release resolution, keep release-asset coverage on emulate but use a focused `httptest` stub for happy-path and malformed tag-ref payload cases.
- For declarative lockfile tests, a first resolve can only write a complete new `*.toolset.lock` entry when provenance metadata comes from a source fetch. A bare cache hit without an existing committed lock cannot synthesize missing `git_sha`, `resolved_from`, or `resolved_at`, so cache-hit verification tests need committed lock metadata rather than cache-only setup.
- Declarative replace overlay paths in `*.toolset.local.json` resolve relative to the overlay file itself, not the caller's working directory. Tests and downstream tooling should anchor expected local package directories to the sibling overlay location.
